# Public documentation quality contract

Groundwork's committed files under `docs/` are the source published by GitHub
Pages. They are not generated by a web framework, and this contract does not
introduce one.

## Applicable targets

- WCAG 2.2 Level AA is the accessibility target for the public documentation.
  A green repository check is automated evidence for its named rules, not a
  conformance claim.
- The current corpus is English, UTF-8, left-to-right content. Every page
  declares a BCP 47-shaped language tag and an explicit base direction. Adding
  another language is a product decision and must preserve correct per-page
  language and direction; it does not require a framework in advance.
- Status, instructions, diagrams, and recovery remain understandable without
  relying on color, motion, images, or TTY-only presentation.

## Automated boundary

`scripts/check-public-docs-quality` uses only the Python standard library. It
checks the committed corpus for bounded UTF-8 input, language and direction,
one main heading and main landmark, one named documentation navigation with
headed groups, named drawer controls, link and media alternatives, static
interaction hooks, reduced-motion and forced-colors boundaries, semantic text
tokens, and deterministic resource budgets. Hostile fixtures prove that the
gate rejects missing locale metadata, a low-contrast text token, and an
oversized JavaScript resource.

The contrast check evaluates the text-token/background pairs Groundwork
actually uses in both Catppuccin themes at a 4.5:1 floor. Decorative palette
colors remain available for borders and fills; normal text uses the semantic
text tokens instead.

## Measured resource baseline

The 2026-08-10 adoption baseline is 50 pages, 1,255,744 total HTML bytes, a
78,785-byte largest page, 22,495 bytes of CSS, and 6,600 bytes of JavaScript.
The shift-left budgets allow measured headroom without asserting field data:

| Resource | Hard repository budget |
| --- | ---: |
| Site pages | 100 |
| One HTML page | 96 KiB |
| All site HTML | 1.5 MiB |
| Shared CSS | 32 KiB |
| Shared JavaScript | 10 KiB |

These are build/resource regression guards, not Core Web Vitals evidence.
Groundwork has no field performance dataset, so it does not claim p75 LCP, INP,
or CLS from repository bytes.

## Browser and human acceptance boundary

Repository-static proof cannot establish runtime focus behavior, 200% text
resize, 320 CSS-pixel reflow, text-spacing overrides, screen-reader output,
forced-colors rendering, touch target behavior, or deployed performance. Review
those boundaries in a real browser and with knowledgeable manual evaluation
when publishing a material interaction or layout change. The mobile drawer's
implemented contract is: the closed drawer is out of sequential focus; opening
moves focus inside and makes the underlay inert; toggle, Escape, or scrim close
it and restore the exact opener; returning to desktop clears mobile-only hidden
and inert state. Copy feedback uses a polite status without taking focus.

Do not add a browser framework, translations, analytics, or real-user monitoring
only to make this contract appear more comprehensive. Add those capabilities
when the product surface and evidence justify their cost.
