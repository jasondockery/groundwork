Personal layer

Customize Groundwork without forking it.

Groundwork is a shared base, not an all-or-nothing box. Keep your personal preferences in local files and machine-local chezmoi data so you can keep pulling updates without losing your own habits.

Rule of thumb

Small personal additions go in .local files. Machine settings go through groundwork-configure and are stored in ~/.config/chezmoi/chezmoi.toml. Full ownership of a managed file means ignore it or maintain your own fork.

#Tier 1: local override files

Use this for the normal case: a few aliases, a different Git preference, or one tmux binding. These files are not managed by Groundwork, and they load after the shared defaults, so your local choices win.

~/.zshrc.localShell aliases, functions, exports, PATH additions, and prompt-adjacent tweaks.
~/.gitconfig.localPersonal Git preferences, conditional includes, aliases, and per-directory identities.
~/.config/tmux/tmux.local.confPersonal tmux options, bindings, status tweaks, and plugin settings.
example local shell override
$ cat >> ~/.zshrc.local <<'EOF'
alias c='clear'
export VISUAL=code
EOF
$ source ~/.zshrc

Some managed files have no .local overlay, including starship.toml, the Ghostty config, ~/.claude/keybindings.json, and Yazi's yazi.toml. For ordinary mapped files, edit the managed source so your change and Groundwork's stay in one place: chezmoi edit --apply ~/.claude/keybindings.json. Yazi is installed through an ownership-guarded apply hook, so use its explicit source seam instead: groundwork-yazi-config diff previews the applied target, groundwork-yazi-config edit opens the exact source template, and chezmoi apply applies the reviewed result. An existing custom file or a changed receipt-owned file stops before apply and remains untouched. groundwork-yazi-config remove --yes deliberately removes only unchanged Groundwork-owned bytes. If you find yourself diverging heavily from upstream in one of these files, that's Tier 3.

#Tier 2: change machine settings

Groundwork stores machine-local settings in ~/.config/chezmoi/chezmoi.toml. Use the guarded settings editor rather than replaying bootstrap: it starts from the current values, changes only what you select, previews the managed-file diff, and applies the selected desired state only after confirmation. update-all owns subsequent upgrades and maintenance.

machine-local settings
$ groundwork-configure
# focused release-posture shortcut:
$ groundwork-profile set preview

Use this tier for independently mutable environment role and stable-versus-preview release posture, dependent Xcode beta, and for revisiting baseline answers such as work-vs-personal machine, Git identity, password manager, code directory, reset behavior, signing key, and Obsidian vault name. Xcode beta is offered only while Xcode is enabled; disabling Xcode clears that dependent preference in the same visible receipt. Plain chezmoi init regenerates from saved answers; it is not the settings editor.

#Tier 3: full ownership

If you want to fully own an entire file, do not keep fighting chezmoi apply. Either ignore that file for this machine or maintain a fork.

Ignore a file locallyUse when one machine should stop receiving a managed file from Groundwork. Add the path to your local chezmoi ignore setup only after deciding you really want full ownership.
Fork GroundworkUse when your whole team or long-term personal setup should diverge from the upstream defaults.
Do not hand-edit managed targets

If you edit ~/.zshrc, ~/.gitconfig, or ~/.config/tmux/tmux.conf directly, the next chezmoi apply can replace your edits. Put personal changes in the local override files instead.
